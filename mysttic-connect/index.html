Mysttic Connect

An integration engine for HL7, X12, DICOM, XML and JSON, FHIR over HTTP included. It is built from the Mirth Connect 4.5.2 code the way the official release was built: the engine is the same, the name and the start scripts are its own.

Copy your Mirth Connect 4.5.2 configuration over, start it, and your channels run as they did before.

The installer and the launcher bring their own Java 17. The .tar.gz and .zip packages carry none: install a 64-bit Java 8 or newer first. Nothing here is signed with a code-signing certificate yet: Windows may show a SmartScreen warning (More info, then Run anyway), and macOS opens the launcher only after “Open Anyway” in System Settings, Privacy & Security. What it is

An engine for your Mirth Connect 4.5.2 channels, built from the same code and compared with the official release file by file, with every difference explained.

The same engine

The Mirth Connect 4.5.2 code, changed only where it shows the product name and where it finds its two configuration files (new names, the old ones still work). The engine version stays 4.5.2, so extensions made for 4.5.2 load as they are, and the database schema is the one Mirth Connect uses.

Built like the original

The same Java 8 compiler and Ant version as the official 4.5.2 build. Every file of the Linux and macOS package is compared with the official 4.5.2 release, and every difference is accounted for: the name, the signatures, the build timestamps and the start scripts, which are our own in place of the install4j launchers.

Tested against the original

99 integration cases run on the official Mirth 4.5.2 and on Mysttic Connect side by side: the same ACKs, responses, files, database rows and e-mails. The only differences are the product name in texts, the default User-Agent and the default alert subject.

A drop-in replacement

Same channels, code templates, configuration map, users, REST API, X-Mirth-* headers and JavaScript API. Nothing to export or import: the installation takes over Mirth's files and database.

Your old configuration works

A conf/mirth.properties copied from Mirth Connect is used in place of the default conf/mysttic.properties, and the log says so. Rename it when it suits you.

Switching from Mirth Connect 4.5.2

Four steps on the server Mirth runs on. Keep the old folder until the new installation has run for a while.

1. Stop Mirth Connect

On Windows stop the “Mirth Connect Service” and set it to start manually: both services use the same ports, and after a reboot both would start.

2. Install

On Windows run the installer into a new folder (the default C:\Program Files\Mysttic Connect) with the ports Mirth used, then stop the “Mysttic Connect Service” it started. Elsewhere, or by hand, unpack the package next to the old installation: it creates the Mysttic Connect folder.

3. Bring the files over

conf/mirth.properties, the whole appdata folder without temp (it holds the keystore, the server id, the configuration map and, with Derby, the database), custom-lib, your own extensions, and whatever you changed among the .vmoptions, conf/dbdrivers.xml, conf/log4j2.properties and conf/mirth-cli-config.properties.

4. Start it

Installed with the installer: start the “Mysttic Connect Service” again (Server Manager or services.msc). From the package: run mcserver, or as a service on Windows install-service.bat /start as Administrator, on Linux and macOS the service you had pointed at the mcservice script. Remove the old service once the new one runs.

Good to know

The engine behaves exactly like Mirth Connect 4.5.2, its bugs and the known vulnerabilities of its libraries included. Run it inside your network, not on the internet.

Windows

Instead of the install4j .exe launchers there are mcserver.bat, mccommand.bat and mcmanager.bat, and the service is Apache Commons Daemon (mcservice.exe). The installers and the package have been tested under Wine, not yet on Windows itself.

No Docker image here

The image that replaces the official Mirth Connect one is not public. The packages above are the way to install from this page.

What carries the new name

The Administrator, Server Manager, CLI and web pages; the files conf/mysttic.properties and logs/mysttic.log; the Windows service; the default User-Agent of the HTTP Sender and the default subject of alert e-mails.

What keeps the old one

Everything channels, data and partners depend on: the com.mirth classes, the JavaScript API, MIRTH in automatic ACKs, the REST paths, the mirthdb database and the mirth-*.jar file names.

Updating the Server Manager from the .tar.gz

For a server installed from the Linux and macOS package or the Windows .zip, version 1.2.0 or later. Check the download against its line in the Server Manager checksums first, with sha256sum (on macOS shasum -a 256).

1. Close the Server Manager

Choose Close Manager in its tray menu. The server and its service keep running: the update replaces only the Server Manager.

2. Unpack over the installation

With the command below, into the folder holding mcserver, for example /opt/Mysttic Connect; only the Server Manager’s files change. On a Windows .zip installation run it without sudo, in a Command Prompt opened as Administrator.

3. Start it again

Start the Server Manager with mcmanager (on Windows mcmanager.exe).

sudo tar -xzf mysttic-connect-manager-<version>-unix.tar.gz -C "<install folder>"
